{% comment %} One partial, four variants: header, hero, inline, map. Pass `variant` (required), plus optional `placeholder` and `types` (comma-separated suggest group keys, e.g. "sites,trails"). Every instance needs a unique id, because the header bar and the hero bar are both on the home page. Ids are built from the variant (sog-search-VARIANT) -- safe only because no single page ever includes the same variant twice, EXCEPT the header bar, which base.html also includes inside .mobile-nav for small screens. That second instance passes id_suffix="-mobile" so the two never collide -- but it still carries the same sog-search--header CLASS as the desktop one, since class is built from variant alone. Anything that needs to target ONE of the two copies (the 900px responsive hide in search.css, for instance) has to scope past .header-actions or .mobile-nav, not just the class. {% endcomment %}
